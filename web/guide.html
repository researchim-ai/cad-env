FIELD GUIDE / RESEARCH INFRASTRUCTURE

A workspace for
verifiable learning.

cad-env connects language and vision models to native CAD execution. The environment supplies a public task, a structured state and optional goal/current images. A model returns one typed JSON action; the environment executes it, validates the result and returns feedback.

Start with the repository

git clone https://github.com/researchim-ai/cad-env.git
cd cad-env

Install the native applications and use the pinned environment matching your task. Geometry execution and Qwen3.5 training use separate environments. Follow the repository’s multi-engine setup guideEN and training lockfiles; the website is a static presentation, not a CAD execution service.

The portable action contract

{"op":"create_body","name":"Body"}
{"op":"sketch_rectangle","name":"Base","body":"Body","length":40,"width":30}
{"op":"pad","name":"Pad","body":"Body","profile":"Base","length":6}
{"op":"finish"}

Actions construct a feature graph with stable identifiers. Parameter edits target named dimensions. Rejected actions preserve the accepted state. The common tool set is deliberately restricted; supporting multiple executors does not mean unrestricted native-API competence.

Generate native-verified tasks

python -m cad_env.multicad generate \
  --output artifacts/my-corpus \
  --engines freecad cadquery \
  --seeds 3 \
  --python .venv-multicad/bin/python

Use the geometry environment for this command. Each dataset needs a fresh output directory. Split lineage, native artifacts, image assets and exports are audited before training. A passing teacher does not establish that a trained model can solve the task.

What training currently does

Qwen3.5-4B learns next-action prediction through BF16 LoRA, adapting language layers plus selected vision attention blocks and the visual merger. Images and observations are excluded from completion loss. Numeric tokens receive additional weight. Checkpoint-500 has been evaluated on native mechanical tasks; skill-retention measurements record their batch execution profile separately.

Read evidence with its scope

  • Report strict native success across all tasks, including failed executions.
  • Count physical designs, not correlated views and engine variants, for confidence intervals.
  • Separate visual selection, dimension reading, construction and repair.
  • Keep test splits sealed during curriculum and checkpoint selection.
  • One-action GRPO is implemented; full multi-turn policy-gradient RL is not yet implemented.
  • Blender execution is available; its expanded dataset remains experimental.

See the training auditEN, benchmark coverageEN and advanced native feature probesEN for implementation details and current boundaries. Advanced probes use a separate contract and are not claimed as model capabilities.
